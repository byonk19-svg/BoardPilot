# Implementation plan

Working goal: a local, editable plywood bookcase planner using genuine cadgen solids, revision-consistent documents and inert portable packages. The original handoff is retained under `handoff/package/woodworking-codex-handoff`. Its schemas and example oracles constrain this implementation.

## Sequence and ownership

1. M0: pinned native Windows runtime, clean-directory panel/asymmetric/occurrence probes, measured drawing/snapshot, reusable R3F instance viewer and actual selection verification. Keep OS security unchanged.
2. M1: pure Pydantic/domain compiler and exact units (domain worker); trusted JSON-driven CAD adapter and core manifests/CSV (CAD worker). Compare all nine original examples, reopen saved solids, inspect proper placement/contacts and validate schema/hash/identity cardinality. Root integrates the command and evidence.
3. M2: root owns SQLite repositories, FastAPI local boundary, bounded dispatcher and Job Object launcher, immutable publication and manual workflow. Tests cover CAS, idempotency, stale/late results, cancellation, timeout, crash and restart. Browser tests cover saved real-CAD create/edit/select/reopen and validation states.
4. M3: cumulative document sets, measured Letter/A4 packet and native metric part pages. Recipe data/graph validation, genuine manufacturer sourcing, separate technical completeness and physical review. Inspect every rendered acceptance PDF page.
5. M4: deterministic guillotine layouts with independent cut simulation, trim/kerf/grain/material checks, unknown prices and decimal purchase/consumption costs. Match baseline and synthetic exact-fit examples.
6. M5: provider-neutral restricted proposals, fake cases, idempotent reservation/application and stale-base conflicts. Keep AI disabled by default; optional live integration requires actual user configuration and separate evidence.
7. M6: inert bounded ZIP import/export and provenance, safe trusted rebuild, setup/production launch scripts, clean-runtime/offline/restart/corruption demonstration, locked dependencies and final acceptance ledger.

Use meaningful failing tests before behavior implementation. No supplied expected values enter production geometry, rendering or planning. No push, deployment, paid call, credential change or physical-review claim is authorized. Preserve parent `.omx` and unrelated work.

## Final checks

Run exact fixture/domain/adapter/API tests, TypeScript/build checks, and actual Playwright workflows. Account for every R/U/G/J/D/S/A/B acceptance row in status/evidence. A milestone requires its entire relevant gate; passing one probe does not establish the full milestone. Do not stop at a milestone when another in-scope dependent slice remains actionable.
